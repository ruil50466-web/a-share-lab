# 智能选股模块 v1：范围与限制

## 当前实现
- 页面：`stock-picker.html`
- 使用只读 Worker：`/api/sectors`、`/api/limit-ups?type=zt`、`/api/limit-ups?type=broken`。Worker 新增分页接口 `/api/stocks?page=1&size=100`，提供全市场快照初始数据源，需部署并验证实际覆盖与字段口径。
- 对涨停池和炸板池候选去重，按连板天数、封板时间、炸板次数、所属行业/板块涨幅与上涨广度做透明规则排序。
- 可选择综合、连板接力、低位启动三种观察模式；可复制结构化 JSON 给 ChatGPT 进一步分析。
- 页面不自动下单，不把评分解释为上涨概率；日期、抓取时间、缺失字段和接口失败均应明确展示。

## 重要边界
这只是候选排序 v1，不是完整全市场选股。当前 Worker 没有批量全市场个股快照和批量历史日线接口，趋势股模型、完整市场广度与公告事件映射尚未实现。候选排序仅覆盖返回的涨停/炸板池，不能将未返回解释为不存在。目前选股页仅在行业名与板块名完全相同时才建立匹配，避免“元件”误配“光学元件”；因此会有漏匹配，不能替代真实板块成分股关系。不同交易板块涨跌幅机制仅作风险提示，ST及特殊股票规则仍需核验。

## 下一阶段
1. 验证新增 `/api/stocks` 分页快照接口的实际返回、字段单位、股票覆盖范围与翻页完整性；字段包括代码、名称、最新价、涨跌幅、成交额、换手率、量比、行业等。
2. 增加批量历史日线/均线字段，支持趋势与五日线回踩候选。
3. 增加稳定的板块成分股映射，避免只靠行业名称字符串。
4. 保存每日扫描结果和后续 1/3/5 日表现，做样本外验证，记录滑点、涨停无法买入及跌停无法卖出。
5. 增加消息事件输入与映射表，但把新闻解释和盘面验证分开记录。

## 使用纪律
分数只用于排序。个股结构、实际买点、市场环境、公告风险和交易可执行性仍需人工/模型二次确认；没有清晰触发条件就不交易。
