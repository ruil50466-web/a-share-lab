# 妖信号历史K线验证：执行说明

## 样本边界
- 只使用 data/observations/yaogu_signal_pool_20260820_20261020.csv。
- 排除 2026 年 6 月开始的旧样本，因为旧样本不完整。
- 不修改原始名单；抓取结果写入 data/derived/，可重复生成。

## 运行
需要 Python 3.9+，只用标准库。在仓库根目录运行：

```bash
python scripts/fetch_yaogu_history.py
```

可选参数：`--count 120 --sleep 0.4`。股票代码从项目现有 Worker 的 /api/stocks 读取，历史日K使用网页现有接口 https://api.ashareapi.com/v1/kline。若接口限流或变更，脚本记录失败，不会用模拟数据补齐。

## 输出
- yaogu_daily_klines.csv：已匹配股票的历史日K。
- yaogu_signal_code_match.csv：匹配到的股票名称与代码。
- yaogu_unmatched_names.csv：未匹配或同名歧义，必须人工核对。
- yaogu_signal_outcomes.csv：每次信号事件的次日、3/5/10日最高收益及3/5日最大回撤。
- yaogu_fetch_errors.csv：接口失败或返回格式不可识别的记录。

## 收益口径
- 信号日收盘价作为统一研究基准，只统计信号日之后的交易日。
- 次日收盘收益 = 次日收盘 / 信号日收盘 - 1。
- N日最高收益 = 信号日之后N个交易日内最高价 / 信号日收盘 - 1。
- N日最大回撤 = 信号日之后N个交易日内最低价 / 信号日收盘 - 1。
- 最高价收益只代表潜在空间，不代表普通账户能在最高价卖出。
- 同一股票不同日期重复入选，保留为不同信号事件；汇总时还要报告按股票去重结果。
- 信号具体出现时点未知，所以信号日收盘基准是事件研究口径，不等于真实可成交收益。
- 当前接口的前复权口径需要复核，且必须检查历史日期是否完整覆盖。

## 统计顺序
1. 检查未匹配名单和抓取错误。
2. 核对日K覆盖范围、字段和复权口径。
3. 先报告覆盖率、缺失率、各窗口收益分布和最大回撤。
4. 再按二进三、三进四、前置涨停、同板块聚集、首次出现批次分组。
5. 最后构造同日期、相似连板阶段的非信号对照组，检验妖信号是否提供增量信息。

这属于历史事件研究，不是成交级回测；尚未处理信号可见时刻、买卖队列、涨跌停无法成交、滑点、费用、停牌与复权因子变化。
