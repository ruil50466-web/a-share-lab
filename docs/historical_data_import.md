# 历史数据导入：先保真，再统计

## 目标

把过去记录的妖股池和后续行情整理成可验证样本。不要把“曾经入选过”直接当成成功，也不要只录入后来涨起来的股票。

## 数据入口

统一先录入 `data/templates/stock_signals.csv`。一行代表一只股票在某个日期、某个信号来源下的一次入选事件。

- 同一股票不同日期再次入选：新增一行，保留不同日期的信号。
- 同一天同一股票出现多个独立信号：可分开记录，但在“信号来源/备注”里写清楚，避免重复计算成独立样本。
- 只知道股票名称、不知道准确日期或代码：先放在临时清单，不能猜日期、代码或收益。
- 没有可靠的后续行情：收益字段留空，不用记忆中的大概涨幅补值。
- 失败、炸板、次日低开、买不到的样本必须保留。

## 最低录入要求

建议先保证每条样本有：信号日期、股票代码、股票名称、概念归属、信号来源、信号出现批次、当日连板高度、买入触发条件、失效条件。随后再补次日收盘涨幅、次日最高涨幅、3日最高涨幅、5日最高涨幅。

收益字段定义要固定：
- 次日收盘涨幅：以前一交易日收盘价为基准，到次日收盘的涨幅。
- 次日最高涨幅：以前一交易日收盘价为基准，次日盘中最高价的涨幅；它不代表能在最高价卖出。
- 3日/5日最高涨幅：以信号日前一交易日收盘价为基准，未来3/5个交易日内最高价的涨幅。若实际采用其他基准，必须先统一口径并写在备注里。

## 验证流程

在仓库根目录运行：

```bash
python scripts/validate_data.py
python scripts/analyze_signals.py
```

验证脚本会检查必需列、日期格式、数字字段和疑似重复记录。它不能验证行情真伪，也不能替代人工核对。
